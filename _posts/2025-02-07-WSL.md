Supongo que todos alguna vez hemos probado el dualboot o el simple uso de nuestro entorno de pentesting en una vm mediante vmware o virtualbox. Si bien se sabe que es tedioso e incomodo algunas veces (mas si no disponemos de mucha ram), tambien suele ser a lo que nos terminamos adaptando, sin embargo, si pudieramos fusionar eso sin problema con Windows sin que interfiera en nuestras tareas diarias? Esto es posible con WSL (Windows Subsystem for Linux), y en este apartado mostrare como hacerlo, asi que sin mas, vamos a eso

![gif](https://media1.tenor.com/m/cP1KLXwUvtYAAAAd/ggf-gato.gif)

>[!info]
Cabe recalcar que todo lo estare haciendo desde un sistema Windows 11, pero si estas en Windows 10, puede que de algunos problemas como me paso a mi :)

Ahora, como se supone que podremos combinar ambos mundos sin corromper nuestro sistema Windows? La verdad es que no lo corrompe, y se instala como cualquier otro programa :)

Pero ahora si, vamos a esto. 

## Instalacion

Como se puede ver, tengo aqui mi sistema Windows 11 recien instalado sin mas:
![](assets/img/setup/wsl1.png)

(Cabe recalcar que este es un Windows 11 Enterprise)

Lo primero que haremos, sera abrir `Powershell` como administrador y escribir el siguiente comando:

```powershell
wsl --install
```

Se deberia de mostrar algo asi:

![](assets/img/setup/wsl2.png)

Aunque aparezca un error, no pasa nada, es comun. Ahora toca reiniciar nuestro sistema.

Una vez reiniciado, si ejecutamos `wsl` veremos este mensaje:

![](assets/img/setup/wsl3.png)

Nos dira que las distros las instalamos desde microsoft store. Sin embargo, tambien lo podemos hacer via consola, primero ejecutando este comando:

```powershell
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
```

Y luego este otro:

```powershell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all
```

![](assets/img/setup/wsl4.png)

No nos deberia de dar error. Luego de esto debemos reiniciar, para luego escribir y ejecutar el siguiente comando:

```powershell
wsl --set-default-version 2
```

![](assets/img/setup/wsl5.png)

Una vez que cambiamos el wsl a la version 2, debemos de reiniciar nuestro sistema nuevamente. Una vez reiniciado, debemos habilitar la virtualizacion para wsl con el siguiente comando:

```powershell
wsl.exe --install --no-distribution
```

Algo que se me olvidaba comentar y es que como estoy haciendo el tutorial en una maquina virtual, tuve que habilitar la version 1 de WSL para poder continuar, aunque no es de preocupacion, ya que los comandos funcionan de la misma forma para WSL2, aunque por obvias razones WSL2 es mucho mejor que WSL1 asi que recomiendo en todo caso WSL2 antes que el 1 c:

Aunque con todo y todo ya podemos instalar la distro que deseemos, aqui la lista completa que WSL admite a la fecha que redacto esto:

![](assets/img/setup/wsl7.png)

Y ahora con esto en cuenta, ya podremos instalar la distro que queramos, como sera un tutorial para complementar Kali/Parrot (O cualquier distro que uses para pentesting) con nuestro Windows sin necesidad de una vm, entonces el comando a ejecutar para instalar la distro es este:

![](assets/img/setup/wsl6.png)

Una vez instalado se vera algo asi:

![](assets/img/setup/wsl8.png)

Si hasta este punto tienes algo similar a lo que se muestra aqui, vas bien :)

Ahora mismo solo toca rellenar los datos tipicos. Una vez llenos ya podremos acceder a nuestro sistema sin problemas:

## Fix netcat bug

Ahora, si bien utilizaramos WSL en modo bridge/mirrored (que es la mejor opcion), puede que netcat nos de un bug que por lo menos a mi me paso, el cual consta en que cuando recibimos una Reverse Shell de un dispositivo local, nuestra terminal se buggea y no podemos mandar comandos remotamente, lo cual es confuso y frustrante, sobre todo si trabajamos con maquinas vulnerables como vulnlab, vulnyx, etc, y no queremos implementar un Kali sobre vmware (lo cual consume mas ram y mas recursos), debemos de hacer el siguiente cambio.

Si instalaste toda la paqueteria de Kali, debes desinstalar netcat con el siguiente comando:

```bash
sudo apt remove netcat-traditional -y
```

Esto desinstala el netcat "corrupto", ahora el que debemos instalar es este:

```bash
sudo apt install netcat-openbsd
```

## Consideraciones

Recomiendo que para exploits y cosas asi tengas tu carpeta separada en Windows para evitar que Defender las borre por accidente, aunque si estan en el host de wsl no pasa nada (o por lo menos en mi caso ha sido asi) pero es una recomendacion si eres como yo y prefieres tener todo en un solo sitio.
